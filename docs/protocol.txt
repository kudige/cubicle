# Cubicle local controller protocol

This document describes the current controller-local Unix socket protocol.

The protocol is intentionally local, small, and provisional. It is stable enough
for tests and the first manager integration slice, but not yet a public API.

## Transport

- Unix-domain stream socket.
- One command line starts each connection.
- Command lines are ASCII command tokens ending in `\n`.
- `\r\n` is accepted and treated the same as `\n`.
- Command lines are limited to 255 bytes before the newline.
- Command lines containing embedded NUL bytes are rejected with
  `error bad_request`.
- Non-attachment commands close after one response.
- Attachment commands keep the socket open until the process exits, the client
  disconnects, or the controller detaches the client.

## Responses

Responses begin with either:

```text
ok
error CODE
```

For responses that include stream bytes, the header line ends with `\n` and the
advertised number of raw bytes follows immediately.

Control responses are buffered per client and flushed from the controller poll
loop. A client that cannot accept its bounded response queue is closed without
failing the controller.

## Commands

### status

Request:

```text
status
```

Response:

```text
ok state=running pid=PID pgid=PGID stdout_offset=N stderr_offset=N
ok state=completed pid=PID pgid=PGID result=N stdout_offset=N stderr_offset=N
```

The completed form is available only while the controller is in its configured
completed retention window.

### read

Request:

```text
read stdout START LENGTH
read stderr START LENGTH
```

Aliases:

```text
read out START LENGTH
read err START LENGTH
```

Response:

```text
ok length=N
<N raw bytes>
```

`N` may be shorter than the requested length if fewer bytes are currently
available.

### metadata

Request:

```text
metadata
```

Response:

```text
ok length=N
<N raw metadata bytes>
```

### events

Request:

```text
events after SEQUENCE LIMIT
```

Response:

```text
ok count=N length=M
<M raw event log bytes>
```

The response includes events with sequence numbers greater than `SEQUENCE`, up
to `LIMIT` records.

### attach stdout/stderr

Request:

```text
attach stdout START
attach stderr START
```

Aliases:

```text
attach out START
attach err START
```

Response:

```text
ok attached stream=stdout start=START length=N
<N raw catch-up bytes><future raw bytes until disconnect>
```

The catch-up bytes come from the persisted stream log. Future bytes are forwarded
as the controller captures them.

### attach stdin

Request:

```text
attach stdin
```

Alias:

```text
attach in
```

Response:

```text
ok attached stream=stdin
error stdin_closed
```

After the response, bytes sent by the client are forwarded to the managed
process stdin until the client disconnects or the controller detaches the client.
`error stdin_closed` is returned when the process was launched with
`--stdin-policy eof`.

### resize

Request:

```text
resize ROWS COLUMNS
```

Response:

```text
ok
error bad_resize
error resize_failed
error resize_unsupported
```

TTY controllers apply the requested window size to the PTY. Stream controllers
return `resize_unsupported`.

### terminate

Request:

```text
terminate
```

Response:

```text
ok
```

The controller sends `SIGTERM` to the managed process group.

### signal

Request:

```text
signal NUMBER
```

Response:

```text
ok
```

The controller sends the requested signal to the managed process group.

## Errors

Current error codes:

- `bad_attach_command`
- `bad_events_command`
- `bad_read_command`
- `bad_request`
- `bad_resize`
- `bad_signal`
- `invalid_attach_start`
- `invalid_range`
- `open_failed`
- `range_past_end`
- `process_completed`
- `read_too_large`
- `request_too_long`
- `resize_failed`
- `resize_unsupported`
- `signal_failed`
- `state_path_too_long`
- `stdin_closed`
- `too_many_clients`
- `unknown_command`
- `unknown_stream`

## Backpressure

Attachment writes are fail-closed. If the controller cannot forward bytes to an
attached output client or cannot forward attached input bytes to child stdin, it
detaches that client and records a detach event.

## Events

The controller writes primitive events to `events.log`.
The journal is opened in append mode, and each event record is emitted with one
append write.

Current event shapes:

```text
seq=N type=process_started controller_id=ID pid=PID pgid=PGID mode=stream
seq=N type=output stream=stdout start=OFFSET length=N
seq=N type=output stream=stderr start=OFFSET length=N
seq=N type=input length=N
seq=N type=terminal_resized rows=ROWS columns=COLUMNS
seq=N type=client_attached stream=stdin|stdout|stderr
seq=N type=client_detached stream=stdin|stdout|stderr
seq=N type=signal_delivered signal=N
seq=N type=process_exited status=exited exit_code=N
seq=N type=process_exited status=signaled signal=N
```

## Metadata

Current metadata fields:

```text
controller_id=ID
mode=stream
pid=PID
pgid=PGID
stdin_policy=open|eof
command=COMMAND
```

When `--state-dir` is omitted, the default state directory is:

```text
.cubicle/controllers/ID
```

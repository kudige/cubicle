# Cubicle implementation plan

## Completed

- Documented the initial architecture in docs/architecture.md.
- Added buildable manager and controller binaries.
- Added shared process mode and state types.
- Implemented process mode/state name helpers.
- Added CTest-based test wiring.
- Added a process helper unit test.
- Added common utility unit tests:
  - generated hex ID shape and buffer validation
  - recursive directory creation and idempotence
  - full-buffer writes through a pipe
- Added manager registry parser unit tests:
  - workspace record parsing
  - process record parsing
  - cursor record parsing
  - primitive event sequence parsing
- Added opt-in gcov/lcov coverage reporting:
  - CUBICLE_ENABLE_COVERAGE CMake option
  - coverage-summary build target
  - test sources filtered from production coverage summary
- Implemented controller stream mode:
  - fork/exec command launch
  - independent child process group
  - stdin/stdout/stderr pipe wiring
  - EOF stdin until attachments exist
  - stdout/stderr mirroring to the invoking terminal
  - child exit status propagation
- Implemented controller TTY mode:
  - allocate a PTY for stdin/stdout/stderr
  - expose combined terminal output through the existing stdout stream
  - forward foreground terminal stdin to the PTY in raw mode
  - propagate initial and changed terminal window size
  - notify the managed process group after TTY window-size changes
  - preserve socket stdin attachment semantics for interactive TTY input
  - support TTY resize over the control socket
  - keep tty-captured-stderr reserved for the later phase
- Added initial durable controller state for stream mode:
  - metadata
  - stdout.log
  - stderr.log
  - sequence-numbered events.log
- Added a controller stream integration test covering output capture, event
  recording, metadata, and child exit status.
- Added a controller TTY integration test covering PTY terminal detection,
  combined output capture, metadata, and exit events.
- Added a controller foreground TTY integration test covering local stdin
  forwarding and SIGWINCH resize propagation.
- Added a controller TTY socket integration test covering stdin attachment and
  resize commands.
- Added a controller-local control socket for stream mode:
  - status queries
  - stdout/stderr range reads from persisted logs
  - terminate requests
  - signal requests
  - signal-delivered primitive events
- Hardened the controller-local control socket:
  - nonblocking listener
  - nonblocking request reads
  - incomplete client requests do not block the controller
  - client write failures do not bring down the controller
  - SIGPIPE is ignored so socket disconnects are ordinary write failures
- Added basic stream attachment semantics:
  - attach stdout/stderr from a persisted offset
  - catch up from persisted logs
  - live follow newly captured output
  - close attachments when the process exits
  - client attached/detached primitive events
- Added stdin attachment for stream mode:
  - attach stdin/in over the control socket
  - forward attached bytes into child stdin
  - record input primitive events
  - support stdin attachment in the Python control socket client
  - Python control socket client can detect controller mode from metadata
  - Python control socket client enables raw terminal input for TTY stdin attachment
  - Python control socket client supports attach tty for bidirectional TTY attachment
  - attach tty defaults to the current output offset for live reattachment
  - attach tty reasserts the active client terminal size without blocking each input chunk
  - oversized explicit output attach catch-up requests return read_too_large
  - terminal_event_recorder.py records TTY input and resize events for E2E tests
  - terminal_resize_e2e_test.py covers foreground+socket and socket+socket resize flows
  - foreground controller input reasserts its terminal size after socket resize
  - controller tracks PTY size and skips unchanged resize requests
- Defined initial stream backpressure behavior:
  - nonblocking attachment writes fail closed
  - slow output clients are detached instead of silently losing bytes
  - stdin clients are detached if their bytes cannot be forwarded
- Documented the current local controller protocol:
  - command syntax
  - response schemas
  - stream read and attach framing
  - current error codes
  - primitive event shapes
- Added explicit stream stdin policy:
  - default --stdin-policy open for stdin attachments
  - --stdin-policy eof for immediate child stdin EOF
  - stdin_policy persisted in metadata
  - attach stdin returns error stdin_closed when stdin is closed
- Hardened default controller state identity:
  - generated controller IDs
  - default state directories use controller IDs instead of child PIDs
  - controller_id persisted in metadata
  - process_started events include controller_id
- Hardened primitive event writes:
  - events.log is opened with append semantics
  - each event record is emitted with one append write
- Added controller recovery read paths:
  - metadata command returns raw metadata through the control socket
  - events after SEQUENCE LIMIT returns primitive events after a cursor
  - Python control socket client supports metadata and events-after
- Defined current event and metadata formats in docs/protocol.txt.
- Added controller daemon mode:
  - --daemon option
  - detach before launching the managed process
  - redirect controller stdin/stdout/stderr to /dev/null
  - keep interaction available through the control socket and persisted logs
- Added the first manager registry slice:
  - workspace records
  - generated stable workspace IDs
  - generated stable process IDs
  - workspace-local friendly names in process records
  - process/controller mapping records
  - process list filtering by workspace name or ID
- Added initial manager/controller routing:
  - process start launches stream controllers as daemons
  - manager allocates stable process IDs before launch
  - controller state is stored under manager state by process ID
  - manager waits for controller socket and metadata
  - manager registers controller ID and direct control socket
  - process resolve returns direct controller details by process ID
  - process resolve supports workspace-local friendly names
  - process I/O remains direct through the controller socket
  - short-lived processes that exit before socket discovery are registered as exited
- Added initial workspace event aggregation:
  - events poll consumes manager-started controller primitive journals
  - manager maintains per-process cursors
  - manager appends workspace-scoped events
  - events can be filtered by workspace name or ID
  - events list reads persisted workspace events
  - events follow performs bounded repeated polling
- Improved the manager event loop:
  - events follow runs until interrupted when --iterations is omitted
  - bounded --iterations mode remains available for tests and scripts
  - follow flushes emitted workspace events after each poll iteration
- Hardened manager persistence in the current CLI architecture:
  - mutating manager commands take an exclusive advisory state lock
  - process IDs are enforced as globally unique
  - process friendly names are enforced as workspace-local unique
- Added a controller control-socket integration test.
- Added a controller attachment integration test.
- Added a controller stdin attachment integration test.
- Added a controller daemon integration test.
- Added a manager registry integration test.
- Added a manager process-start integration test.

- Split the controller implementation into focused internal modules:
  - CLI entrypoint
  - stream process lifecycle
  - durable state and event journaling
  - control socket protocol and attachments
  - shared controller I/O helpers
- Hardened controller command-line protocol parsing:
  - accept LF and CRLF request terminators
  - reject embedded NUL bytes as bad_request
  - document ASCII command tokens with raw byte response payloads
- Hardened controller stream lifecycle:
  - keep the control socket reachable after stdout/stderr EOF while the child is alive
  - reap child exit from the stream loop without losing the recorded exit status
  - regress output-EOF-before-child-exit control socket behavior
- Hardened controller state initialization failure paths:
  - initialize controller state before failure cleanup can use it
  - separate child exit status calculation from durable exit-event recording
  - avoid exit-event writes when the event journal was not opened
- Added controller client-failure isolation regressions:
  - oversized requests fail only that client
  - malformed attach requests fail only that client
  - later status and terminate requests continue to work
- Hardened controller state directory creation:
  - create parent directories and allow an existing empty leaf state directory
  - fail normal launch instead of truncating reused state
  - regress reused state directory preservation
- Hardened controller control socket creation:
  - do not unlink live socket paths
  - do not unlink non-socket filesystem entries
  - replace stale socket paths only
  - set control socket permissions explicitly
- Finished the current stream control response semantics:
  - queue bounded per-client control responses
  - flush queued responses from the stream poll loop with POLLOUT
  - cover slow large-read clients while other control requests continue
- Added opt-in controller completed-state retention:
  - --completed-retention-ms N keeps the control socket available after exit
  - completed status includes the child result and final stream offsets
  - read-only status, metadata, events, and stream reads remain available
  - interactive commands fail with process_completed

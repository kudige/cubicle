# Cubicle manager registry

The current manager implementation supports foreground CLI operations for
persistent registry state and an initial long-running daemon lifecycle over a
Unix socket. Stream process I/O still routes directly to per-process controller
sockets.

## State directory

The default state directory is:

```text
.cubicle/manager
```

Use `--state-dir DIR` to override it.

## Files

### workspaces.tsv

```text
workspace_id<TAB>workspace_name<TAB>workspace_directory
```

Workspace names are unique.

### processes.tsv

```text
process_id<TAB>workspace_id<TAB>friendly_name<TAB>mode<TAB>state<TAB>controller_id<TAB>control_socket<TAB>cwd
```

The current process state written by `process register` is `running`.
Process IDs are globally unique. Friendly names are unique within a workspace.

### manager.lock

Mutating manager commands take an exclusive advisory lock on `manager.lock`
while reading and writing registry state.

### manager-id

The daemon stores its stable manager ID in `manager-id` when first queried.

### manager.sock

The default manager daemon Unix socket path is `DIR/manager.sock`. A daemon
command may override it with `--control-socket PATH`.

## Commands

### workspace create

```console
cubicle-manager --state-dir DIR workspace create "Project A"
```

Creates a workspace record with a generated stable workspace ID.
Fails if a workspace with the same name already exists.

### workspace list

```console
cubicle-manager --state-dir DIR workspace list
```

Prints:

```text
workspace_id<TAB>workspace_name<TAB>workspace_directory
```

### process register

```console
cubicle-manager --state-dir DIR process register \
  --workspace "Project A" \
  --friendly-name make-1 \
  --mode stream \
  --controller-id CONTROLLER_ID \
  --control-socket /path/to/control.sock
```

Registers a process/controller mapping. `--workspace` may be either a workspace
name or workspace ID. `--process-id ID` may be supplied; otherwise the manager
generates a stable process ID.

Only `stream` mode can be registered currently.
Registration fails if the process ID already exists or the friendly name is
already present in the target workspace.

### process list

```console
cubicle-manager --state-dir DIR process list
cubicle-manager --state-dir DIR process list --workspace "Project A"
```

Prints:

```text
process_id<TAB>workspace_id<TAB>friendly_name<TAB>mode<TAB>state<TAB>controller_id<TAB>control_socket<TAB>cwd
```

### process resolve

```console
cubicle-manager --state-dir DIR process resolve PROCESS_ID
cubicle-manager --state-dir DIR process resolve make-1 --workspace "Project A"
```

Resolves a process ID globally, or a friendly name within a workspace. Friendly
name resolution requires `--workspace`.

Prints the direct controller details:

```text
process_id<TAB>workspace_id<TAB>friendly_name<TAB>mode<TAB>state<TAB>controller_id<TAB>control_socket<TAB>cwd
```

### process start

```console
cubicle-manager \
  --state-dir DIR \
  --controller-bin /path/to/cubicle-controller \
  process start \
  --workspace "Project A" \
  --friendly-name make-1 \
  --mode stream|tty|term \
  --stdin-policy eof \
  -- make
```

Starts a stream, TTY, or term-mode controller as a daemon, waits for its control
socket and metadata, then registers the process/controller mapping. Plain TTY
mode routes stdin, stdout, and stderr through a PTY and exposes combined
output. Term mode routes stdin/stdout through a PTY while retaining stderr as a
separate stream.
Start fails before launching a controller if the friendly name is already
present in the target workspace.

Controller state is stored under:

```text
DIR/controllers/PROCESS_ID
```

The returned `control_socket` is the direct controller socket clients should use
for high-volume process I/O.

If a process exits before the manager observes a live control socket, the
manager still registers it as `exited` when controller metadata and a
`process_exited` event are available.

### events poll

```console
cubicle-manager --state-dir DIR events poll
cubicle-manager --state-dir DIR events poll --workspace "Project A"
```

Consumes primitive controller events from manager-started process state
directories, appends workspace-scoped records to `workspace-events.log`, prints
new records, and updates per-process cursors in `cursors.tsv`.

Printed and persisted workspace event shape:

```text
workspace_id<TAB>process_id<TAB>friendly_name<TAB>primitive_event_line
```

Only events after the last consumed cursor are emitted on subsequent polls.

### events list

```console
cubicle-manager --state-dir DIR events list
cubicle-manager --state-dir DIR events list --workspace "Project A"
```

Lists aggregated records already persisted in `workspace-events.log`.

### events follow

```console
cubicle-manager --state-dir DIR events follow --interval-ms 250
cubicle-manager --state-dir DIR events follow --iterations 10 --interval-ms 250
cubicle-manager --state-dir DIR events follow --workspace "Project A" --iterations 10
```

Runs the manager event loop and repeatedly polls for new events. Follow runs
until interrupted by default. `--iterations` can bound the loop for tests and
scripts. New records are flushed after each poll iteration.

### daemon

```console
cubicle-manager --state-dir DIR daemon
cubicle-manager --state-dir DIR daemon --foreground
cubicle-manager --state-dir DIR daemon --control-socket /path/to/manager.sock --event-interval-ms 250
```

Runs the persistent manager daemon. By default the command prints the manager
startup identity, opens the configured listener, then detaches from the current
terminal. Use `--foreground` to keep the manager attached to the invoking
process, which is useful under tests and process supervisors.

The lifecycle socket currently supports `ping`, `status`, and `shutdown` as a
narrow bootstrap surface for the transport-neutral API implementation. While
running, the daemon also owns workspace event aggregation and updates
`workspace-events.log` and `cursors.tsv` periodically.

# Cubicle manager registry

The current manager implementation is a foreground CLI for persistent registry
operations and stream controller launch. It does not run a long-lived event loop
yet.

## State directory

The default state directory is:

```text
.cubicle/manager
```

Use `--state-dir DIR` to override it.

## Files

### workspaces.tsv

```text
workspace_id<TAB>workspace_name
```

### processes.tsv

```text
process_id<TAB>workspace_id<TAB>friendly_name<TAB>mode<TAB>state<TAB>controller_id<TAB>control_socket
```

The current process state written by `process register` is `running`.

## Commands

### workspace create

```console
cubicle-manager --state-dir DIR workspace create "Project A"
```

Creates a workspace record with a generated stable workspace ID.

### workspace list

```console
cubicle-manager --state-dir DIR workspace list
```

Prints:

```text
workspace_id<TAB>workspace_name
```

### process register

```console
cubicle-manager --state-dir DIR process register \
  --workspace "Project A" \
  --friendly-name make-1 \
  --mode stream \
  --controller-id CONTROLLER_ID \
  --control-socket /path/to/control.sock
```

Registers a process/controller mapping. `--workspace` may be either a workspace
name or workspace ID. `--process-id ID` may be supplied; otherwise the manager
generates a stable process ID.

Only `stream` mode can be registered currently.

### process list

```console
cubicle-manager --state-dir DIR process list
cubicle-manager --state-dir DIR process list --workspace "Project A"
```

Prints:

```text
process_id<TAB>workspace_id<TAB>friendly_name<TAB>mode<TAB>state<TAB>controller_id<TAB>control_socket
```

### process resolve

```console
cubicle-manager --state-dir DIR process resolve PROCESS_ID
cubicle-manager --state-dir DIR process resolve make-1 --workspace "Project A"
```

Resolves a process ID globally, or a friendly name within a workspace. Friendly
name resolution requires `--workspace`.

Prints the direct controller details:

```text
process_id<TAB>workspace_id<TAB>friendly_name<TAB>mode<TAB>state<TAB>controller_id<TAB>control_socket
```

### process start

```console
cubicle-manager \
  --state-dir DIR \
  --controller-bin /path/to/cubicle-controller \
  process start \
  --workspace "Project A" \
  --friendly-name make-1 \
  --mode stream \
  --stdin-policy eof \
  -- make
```

Starts a stream-mode controller as a daemon, waits for its control socket and
metadata, then registers the process/controller mapping.

Controller state is stored under:

```text
DIR/controllers/PROCESS_ID
```

The returned `control_socket` is the direct controller socket clients should use
for high-volume process I/O.

If a process exits before the manager observes a live control socket, the
manager still registers it as `exited` when controller metadata and a
`process_exited` event are available.

### events poll

```console
cubicle-manager --state-dir DIR events poll
cubicle-manager --state-dir DIR events poll --workspace "Project A"
```

Consumes primitive controller events from manager-started process state
directories, appends workspace-scoped records to `workspace-events.log`, prints
new records, and updates per-process cursors in `cursors.tsv`.

Printed and persisted workspace event shape:

```text
workspace_id<TAB>process_id<TAB>friendly_name<TAB>primitive_event_line
```

Only events after the last consumed cursor are emitted on subsequent polls.

### events list

```console
cubicle-manager --state-dir DIR events list
cubicle-manager --state-dir DIR events list --workspace "Project A"
```

Lists aggregated records already persisted in `workspace-events.log`.

### events follow

```console
cubicle-manager --state-dir DIR events follow --interval-ms 250
cubicle-manager --state-dir DIR events follow --iterations 10 --interval-ms 250
cubicle-manager --state-dir DIR events follow --workspace "Project A" --iterations 10
```

Runs the manager event loop and repeatedly polls for new events. Follow runs
until interrupted by default. `--iterations` can bound the loop for tests and
scripts. New records are flushed after each poll iteration.
